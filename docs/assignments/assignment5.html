The assignment

In class we built a house price model for Philadelphia. Now your team does it for a city you haven’t modeled: Chicago.

The Cook County Assessor’s Office has to value every home in the county, including the vast majority that didn’t sell this year. Assessments drive property tax bills. When they’re wrong in a systematic way, some households pay more than their share. A 2017 Chicago Tribune investigation, “The Tax Divide,” found exactly that in Cook County: lower-value homes were assessed at higher shares of their worth than expensive ones.

Build a model that predicts single-family sale prices in Chicago, 2023–2025, using only the tools from this course. The file contains only features of the house itself. Everything about location is yours to build.

A real test

File What’s in it
chicago_train.csv About 80% of the houses, with sale prices
chicago_test.csv The other 20%, without sale prices. You predict them; we score you.

The test houses were held out by house, not by sale, so a house that sold twice is entirely on one side. Your CV RMSE is your estimate. Your test RMSE is the truth. If they’re far apart, something leaked.

Due: Friday, October 30. All teammates renders the file on their portfolio and every member submits that link on Canvas. One teammate uploads team_XX_predictions.csv.

Individual accountability: Q7 on October 30 asks each of you about this model: which features you used and why, your CV and test RMSE, and where the model fails worst. Make sure everyone can explain all of it.

Rules

Important1. Clean training rows once, in Part 1. Never drop test rows.

You must predict every test house, so fill NAs in a feature rather than filtering.

2. Stay inside the time window

Open data from 2023–2025 only.

3. No leakage

Nothing built from sale prices. Would the Assessor have this number for a house that didn’t sell?

4. The outcome stays in dollars

Transform predictors, not sale_price.

5. No prices from the test fold or the future

No features built from other houses’ sale prices.

Answer: What in your exploration shaped your modeling choices?

Houses with similar sizes sell for very different prices, so we did not expect house characteristics alone to explain everything. We started with a structure-only model, then tested squared size and age terms and an alternative using log size. The map also gave us a reason to test location features. We used cross-validation to check whether those additions helped.

We kept the unusually low and high prices because we did not have enough evidence to call them errors. That choice has consequences: expensive sales can drive dollar RMSE, while a relatively small dollar error can be a large percentage of a cheap house’s price. We return to both issues in Part 4.

Fill missing predictors

We need a prediction for every test house, so we fill missing predictors instead of dropping test rows. Week 8 uses replace_na() and median() for this. During CV, we calculate the medians from the fitting fold only. For the final test predictions, we use medians from all cleaned training rows.

The reference argument tells the function which rows provide those medians. Writing the columns separately lets us see exactly what gets filled.

Code 
fill_missing <- function(data, reference) {
  data <- st_drop_geometry(data)
  reference <- st_drop_geometry(reference)

  data %>%
    mutate(
      lotsize_acre = replace_na(lotsize_acre,
        median(reference$lotsize_acre, na.rm = TRUE)),
      num_half_baths = replace_na(num_half_baths,
        median(reference$num_half_baths, na.rm = TRUE)),
      num_fireplaces = replace_na(num_fireplaces,
        median(reference$num_fireplaces, na.rm = TRUE)),

Cross-validation and spatial weights

This loop follows Week 7. We fill missing predictors using the fitting rows before calling lm(). We keep the raw predictions, including negative values, when we calculate error. We do not replace them with zero. Negative predictions show where this linear model gives an impossible house value.

Code 
cv_predictions <- function(formula, data, fold_id) {
  predictions <- rep(NA_real_, nrow(data))

  for (k in 1:10) {
    validation <- fold_id == k
    fitting <- fill_missing(data[!validation, ], data[!validation, ])
    validating <- fill_missing(data[validation, ], data[!validation, ])

    fit <- lm(formula, data = fitting)
    predictions[validation] <- predict(fit, newdata = validating)
  }

  predictions
}

morans_i <- function(values, weights) {
  moran(values, weights, n = length(values), S0 = Szero(weights))$I
}

Locate the remaining clusters with LISA

Global Moran’s I gives us one summary of spatial clustering. The Week 8 LISA map helps us see where it occurs. We use the slides’ helper, five-neighbor weights, 499 permutations and a 0.01 significance threshold. We set the seed for reproducibility.

High–High means a house and its neighbors have above-average residuals. Low–Low means below-average residuals. Since the residual is actual minus predicted, these usually indicate areas of underprediction and overprediction, respectively. The categories are relative to the mean residual, not strictly to zero. These are exploratory maps with many local tests, not proof of a cause.

Code 
lisa_quads <- function(resid, w, alpha = 0.01) {
  lm_perm <- localmoran_perm(resid, w, nsim = 499)
  z <- resid - mean(resid)
  neighbor_lag <- lag.listw(w, z)
  p <- lm_perm[, "Pr(z != E(Ii)) Sim"]

  case_when(
    is.na(p) | p >= alpha ~ "Not significant",
    z > 0 & neighbor_lag > 0 ~ "High-High",
    z < 0 & neighbor_lag < 0 ~ "Low-Low",
    z > 0 & neighbor_lag < 0 ~ "High-Low",
    TRUE ~ "Low-High"
  )
}

## The assignment

In class we built a house price model for Philadelphia. Now your team does it for a city you haven't modeled: **Chicago**.

The Cook County Assessor's Office has to value every home in the county, including the vast majority that didn't sell this year. Assessments drive property tax bills. When they're wrong in a systematic way, some households pay more than their share. A 2017 *Chicago Tribune* investigation, "The Tax Divide," found exactly that in Cook County: lower-value homes were assessed at higher shares of their worth than expensive ones.

Build a model that predicts **single-family sale prices in Chicago, 2023–2025**, using only the tools from this course. The file contains **only features of the house itself**. Everything about location is yours to build.

### Fill missing predictors

We need a prediction for every test house, so we fill missing predictors instead of dropping test rows. Week 8 uses `replace_na()` and `median()` for this. During CV, we calculate the medians from the fitting fold only. For the final test predictions, we use medians from all cleaned training rows.

The `reference` argument tells the function which rows provide those medians. Writing the columns separately lets us see exactly what gets filled.

```{r}
#| label: fill-missing
fill_missing <- function(data, reference) {
  data <- st_drop_geometry(data)
  reference <- st_drop_geometry(reference)

  data %>%
    mutate(
      lotsize_acre = replace_na(lotsize_acre,
        median(reference$lotsize_acre, na.rm = TRUE)),
      num_half_baths = replace_na(num_half_baths,
        median(reference$num_half_baths, na.rm = TRUE)),
```

### Write the model formulas

We compare house attributes, squared terms and timing, log size, distance, squared distance, rings, a size-by-ring interaction, and tract fixed effects. After inspecting negative predictions, we also compare three size alternatives and an age-by-ring interaction. Squared terms let a relationship bend. The interaction lets the size slope differ across rings. Tract fixed effects allow different intercepts across tracts. The outcome stays in dollars.

### Cross-validation and spatial weights

This loop follows Week 7. We fill missing predictors using the fitting rows before calling `lm()`. We keep the raw predictions, including negative values, when we calculate error. We do not replace them with zero. Negative predictions show where this linear model gives an impossible house value.

```{r}
#| label: validation-functions
cv_predictions <- function(formula, data, fold_id) {
  predictions <- rep(NA_real_, nrow(data))

  for (k in 1:10) {
    validation <- fold_id == k
    fitting <- fill_missing(data[!validation, ], data[!validation, ])
    validating <- fill_missing(data[validation, ], data[!validation, ])

    fit <- lm(formula, data = fitting)
    predictions[validation] <- predict(fit, newdata = validating)
  }

  predictions
}

morans_i <- function(values, weights) {
  moran(values, weights, n = length(values), S0 = Szero(weights))$I
```

### Locate the remaining clusters with LISA

Global Moran's I gives us one summary of spatial clustering. The Week 8 LISA map helps us see where it occurs. We use the slides' helper, five-neighbor weights, 499 permutations and a 0.01 significance threshold. We set the seed for reproducibility.

High–High means a house and its neighbors have above-average residuals. Low–Low means below-average residuals. Since the residual is actual minus predicted, these usually indicate areas of underprediction and overprediction, respectively. The categories are relative to the mean residual, not strictly to zero. These are exploratory maps with many local tests, not proof of a cause.

```{r}
#| label: lisa-diagnostics
lisa_quads <- function(resid, w, alpha = 0.01) {
  lm_perm <- localmoran_perm(resid, w, nsim = 499)
  z <- resid - mean(resid)
  neighbor_lag <- lag.listw(w, z)
  p <- lm_perm[, "Pr(z != E(Ii)) Sim"]

  case_when(
    is.na(p) | p >= alpha ~ "Not significant",
    z > 0 & neighbor_lag > 0 ~ "High-High",
    z < 0 & neighbor_lag < 0 ~ "Low-Low",
    z > 0 & neighbor_lag < 0 ~ "High-Low",
    TRUE ~ "Low-High"
  )
}
```

## Part 6: Reflection (about 300 words, as a team)

1. **Read one coefficient twice:** once as β̂, once for what it does to ŷ.
2. **Would you hand this model to the Assessor?** What would you warn them about?

We started with house characteristics, then added location because similar houses can sell for different prices across Chicago. We compared squared terms, log size, distance, rings, interactions and tract fixed effects. Adding tract-specific size slopes and an age-by-ring interaction gave the lowest CV RMSE among the tested formulas. We chose among them using the same grouped CV folds. These fitted relationships describe associations; they do not tell us what changing a house or neighborhood would cause.

Our central-air coefficient is `r money(unname(coef(m_final)["central_air"]))`. As beta-hat, it is the estimated price difference between the supplied central-air categories, holding the other predictors fixed. For y-hat, switching that indicator from 0 to 1 changes the predicted price by that amount. We cannot interpret it as the return from installing air conditioning because condition and renovations may also differ between houses.

We would not give this model to the Assessor for operational use yet. It improves on the baseline, but the residual maps and LISA results show where further checks are needed. Dollar RMSE can hide large proportional errors for inexpensive houses. Income-group comparisons help us describe that concern, but tract income is not an owner's income and cannot establish individual fairness.

We removed bundled transactions rather than guessing how to divide their prices. We kept both price tails because we could not justify excluding them. Grouping rounded coordinates helps with repeated sales, but verified parcel IDs would be better. Our CV score also influenced model selection, so it is not an independent final test. Before using this model for assessments, we would evaluate a later year and held-out geographic areas, verify condition and transaction details, and investigate impossible predictions. We would follow Week 8's approach of checking residual clusters and measuring a plausible missing feature before adding it. We should not assume a more complicated model will fix every error.
